# System Architecture

## 1. High-Level Architecture
The system consists of independent microservices for robust separation of concerns, scalability, and security.

*   **Frontend (Angular):** Trading dashboard, portfolio visualization, risk controls, and Kill Switch.
*   **API Gateway & Backend (Java Spring Boot):** Handles REST APIs, user authentication, and orchestrates the database interactions.
*   **Trading Orchestrator (Python):** Manages the central loop of data ingestion, AI-agent deliberation, risk verification, and order execution.
*   **Market Data Service (Python):** Connects to Kite WebSocket and persists tick data/candles to Redis.
*   **Database (PostgreSQL):** Stores trade ledgers, risk limits, protected holdings, and backtest results.
*   **Cache/Event Bus (Redis):** Handles live market data streaming and inter-service messaging.

## 2. Multi-Agent AI System
The intelligence layer uses a committee approach:

1.  **Data Ingestion Agent:** Cleans and normalizes WebSocket data.
2.  **Technical Agent:** Computes indicators (RSI, MACD, Bollinger Bands) and outputs a quantitative score.
3.  **Fundamental & Sentiment Agent:** Evaluates earnings, news, and sector momentum.
4.  **Market Regime Agent:** Identifies current market states (Bull, Bear, Sideways).
5.  **Bull/Bear Debate Agents:** One argues for the trade, the other argues against it.
6.  **Signal Aggregator:** Produces a deterministic score (e.g., 85/100) based on weighted agent inputs.

## 3. Risk & Safety Architecture
The **Risk Engine** acts as an impassable firewall between the AI Agents and the Execution Engine.

*   **Protected Asset Guard:** Before any SELL signal is processed, the Risk Engine checks the `PROTECTED_HOLDINGS` table. If the symbol exists, the trade is rejected.
*   **Capital Ledger:** Ensures the system only uses `STRATEGY_CAPITAL_LEDGER` (e.g., ₹13,000) and never touches external funds.
*   **Deterministic Limits:** Enforces configurable limits (`MAX_DAILY_LOSS`, `MAX_DRAWDOWN`, `MAX_RISK_PER_TRADE`).
*   **Kill Switch:** Immediately halts new orders and optionally closes open strategy positions.

## 4. Execution Flow
1. **Signal** generated by AI Aggregator.
2. **Risk Approval** validates constraints.
3. **Execution Service** maps to Kite Order parameters and assigns an Idempotency ID.
4. **Order Placement** via Kite Connect API.
5. **Ledger Update** upon order fulfillment.
